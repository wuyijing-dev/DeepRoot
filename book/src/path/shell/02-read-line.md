# 1.2.2 `read_line` 与共享串口

这一页只讲：**为什么 shell 读输入时既像轮询，又像能交互。**

## 1. 最短逻辑

```text
debug_read_byte()
  >=0  -> 得到字节
  <0   -> yield 再试
回车    -> 结束一行
退格    -> 删除一个字符并回显
其它控制字符 -> 丢弃
```

## 2. 为什么你会感觉“好像输入不灵”

因为串口是共享的：

- 内核日志在写
- shell 在回显
- 其它任务也可能输出

所以问题常常不是“按键没收到”，而是“屏幕被别的输出打断了视觉连续性”。

## 3. 关键内核依赖

`SYS_DEBUG_READ` 最终走到 `sbi::console_getchar()`。  
这就是为什么 getchar EID 一错，shell 会立刻表现异常。
