# 1.2.3 `run_path` 与前台等待

这一页只讲：**为什么 `run hello` 后提示符不会立刻回来。**

## 1. 最短逻辑

```text
id = exec(path)
失败 -> 打印 exec failed
成功 -> while wait(id) == -11: yield
```

## 2. 这意味着什么

shell 把 `run` 做成了**前台运行模型**：

- 子任务在前面跑
- shell 在后面等待
- 直到 child 退出并被回收，提示符才回来

## 3. 为什么这对新手反而更清楚

因为它避免了“后台任务、作业控制、信号”这些复杂度。  
先把“运行一个用户程序、等它结束”这件事讲清楚，再考虑更复杂模型。
